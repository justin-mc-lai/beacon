# Beacon v1.3.3 Minimal HUD 设计场景（极简）

**Date**: 2026-04-16  
**Version**: v1.3.3  
**Status**: Design Draft (Scenario-Focused)

---

## 1. 目标

把 HUD 收敛成一句话：

> **默认只回答“我现在在哪、是否卡住、下一步是什么”。**

不做 TUI，不做仪表盘，不引入新的公开主命令。

---

## 2. 七维头暴（收敛版）

### 2.1 用户维度

- 核心用户：正在执行 `6+3` 主链的人类操作者
- 次级用户：维护者/高级用户（只在排障时看细节）
- 排斥用户：不希望被 runtime/bridge/adapter 细节打扰的新用户

### 2.2 场景维度

- 高频场景：`help/status` 看当前阶段和下一步
- 关键场景：`implement` 执行中（single/team/ralph）
- 阻断场景：Ralph circuit warn/trip，或 QA blocked

### 2.3 业务维度

- HUD 不是新能力入口，是降低认知成本的“状态压缩层”
- 成功标志：用户不需要理解内部 lane 也能决策下一步

### 2.4 技术维度

- 只复用已有状态源：`help_support`、`ralph_runtime`、`team_hud`
- 不新增复杂状态机，只新增最小渲染契约

### 2.5 体验维度

- 默认 1 行
- 执行中 2 行
- 有阻断才 3 行

### 2.6 价值维度

- 功能价值：更快决策下一步
- 治理价值：把复杂度留在机器面

### 2.7 风险维度

- 风险：字段过多导致 HUD 变成噪音
- 缓解：严格 line budget + 字段白名单

---

## 3. 极简设计原则

1. **Line Budget 固定**
- L1: 始终显示
- L2: 仅执行阶段显示
- L3: 仅阻断/告警显示

2. **摘要优先**
- 人类面只看摘要
- JSON/artifact 承担全量细节

3. **不扩命令面**
- 不新增一级命令
- 挂接在现有 `help/status/implement` 输出

---

## 4. HUD 核心场景清单

| 场景 | 触发条件 | 行数 | 用户要回答的问题 |
|------|---------|------|------------------|
| S1 主链空闲 | 有 feature，未进入执行 | 1 | 现在在哪个阶段？ |
| S2 Single 执行 | implement mode=single | 2 | 正在做什么、进度如何？ |
| S3 Team 执行 | implement mode=team | 2 | 并行执行是否在推进？ |
| S4 Ralph 执行 | implement mode=ralph | 2 | 当前轮次、是否接近放行？ |
| S5 Warn 阻断前 | circuit/status=warn | 3 | 是否需要人工介入？ |
| S6 Trip/Blocked | circuit/status=trip 或 qa blocked | 3 | 为什么卡住、下一步命令是什么？ |

---

## 5. 场景输出模板（极简）

### S1 主链空闲（1 行）

```text
[beacon:vX] docs:vY | feature | [prd|user-story|test-case|implement|qa|release] | next:<cmd>
```

### S2 Single（2 行）

```text
[beacon:vX] docs:vY | feature | [implement:single] | next:qa
▸ file:<current> done:<n> elapsed:<t>
```

### S3 Team（2 行）

```text
[beacon:vX] docs:vY | feature | [implement:team] | next:qa
▸ workers:<k> progress:<done>/<total> elapsed:<t>
```

### S4 Ralph（2 行）

```text
[beacon:vX] docs:vY | feature | [implement:ralph] | next:<action>
▸ round:<r> stop:<state|N/A> circuit:<ok|warn|trip> elapsed:<t>
```

### S5 Warn（3 行）

```text
[beacon:vX] docs:vY | feature | [implement:ralph] | next:<action>
▸ round:<r> circuit:warn elapsed:<t>
⚠ blocker:<short_reason> | cmd:<recommended_command>
```

### S6 Trip/Blocked（3 行）

```text
[beacon:vX] docs:vY | feature | [implement|qa] | blocked
▸ state:<trip|blocked> reason:<reason_code>
⛔ cmd:<single_recommended_command>
```

---

## 6. 字段白名单（只保留必要）

### L1 必要字段

- `beacon_version`
- `docs_version`
- `feature`
- `current_stage_or_mode`
- `next_action_or_blocked`

### L2 必要字段（执行阶段）

- `mode`
- `progress`（single: done/team: done-total/ralph: round）
- `elapsed`

### L3 必要字段（仅告警）

- `blocker_short_reason`
- `recommended_command`

---

## 7. 明确不做

- 不做多窗口 dashboard
- 不做 token 成本面板
- 不做交互式键盘控制
- 不做自定义主题系统
- 不把 HUD 升级为独立产品面

---

## 8. 验收标准（场景导向）

1. 默认不超过 2 行；仅阻断时 3 行
2. 新用户能在 3 秒内读出“阶段 + 下一步”
3. Ralph warn/trip 必须给出单一推荐命令
4. Team 模式不暴露 worker 细节列表，只给总量进度
5. 所有细节都能在 JSON/artifact 找到，但默认不挤到 HUD

---

## 9. 与 v1.3.3 主线的关系

- 符合 core slimming：HUD 仅做状态压缩，不引入新主面
- 符合 compatibility demotion：HUD 不展示 external adapters 为默认能力
- 符合 doctor 迁移策略：blocked 时优先推荐 doctor 迁移命令
