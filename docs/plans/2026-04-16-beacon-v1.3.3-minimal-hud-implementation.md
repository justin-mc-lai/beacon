# Beacon v1.3.3 Minimal HUD 实施计划（极简场景版）

**Date**: 2026-04-16  
**Version**: v1.3.3  
**Status**: Implementation Draft

---

## 1. 实施目标

按设计文档的 `S1-S6` 场景落地最小 HUD：

- 默认 1 行
- 执行中 2 行
- 告警/阻断 3 行

只做状态压缩，不扩命令面。

---

## 2. 现有能力复用

直接复用现有状态源，不另起 runtime：

- Ralph 状态：`beacon/utils/ralph_runtime.py`
- Team HUD 路径：`beacon/utils/subagent_runtime.py`
- 统一执行面聚合：`beacon/utils/help_support.py`
- 人类输出面：`beacon/commands/help.py`、`beacon/commands/status.py`

---

## 3. 最小数据契约

新增统一 HUD payload（可放在 `help_support` 层）：

```json
{
  "beacon_version": "v1.3.3",
  "docs_version": "v1.3.3",
  "feature": "feature-name",
  "stage": "prd|user-story|test-case|implement|qa|release",
  "execution": {
    "mode": "single|team|ralph",
    "elapsed": "1m30s",
    "progress": {
      "done": 0,
      "total": 0,
      "round": 0
    },
    "circuit_status": "ok|warn|trip"
  },
  "blocker": {
    "level": "none|warn|blocked",
    "reason": "",
    "recommended_command": ""
  },
  "next_action": ""
}
```

约束：

- 人类渲染只消费必要字段
- 机器细节继续走原有 JSON/artifacts

---

## 4. 场景到渲染规则映射

| 场景 | 判定 | 输出 |
|------|------|------|
| S1 | `stage != implement` 且 `blocker.level=none` | L1 |
| S2 | `stage=implement` `mode=single` `blocker.level=none` | L1+L2 |
| S3 | `stage=implement` `mode=team` `blocker.level=none` | L1+L2 |
| S4 | `stage=implement` `mode=ralph` `blocker.level=none` | L1+L2 |
| S5 | `blocker.level=warn` | L1+L2+L3 |
| S6 | `blocker.level=blocked` 或 `circuit_status=trip` | L1+L2+L3 |

---

## 5. 代码切片（最小改动）

### Slice A：HUD 渲染器

新增：

- `beacon/utils/minimal_hud.py`

职责：

- `build_minimal_hud_lines(payload) -> list[str]`
- 严格保证 1-3 行

### Slice B：状态聚合

修改：

- `beacon/utils/help_support.py`

职责：

- 在现有 `execution_surface` 基础上补齐最小 HUD payload
- blocker 推荐命令优先使用 doctor 迁移命令（当 compatibility 阻断）

### Slice C：命令输出挂接

修改：

- `beacon/commands/help.py`
- `beacon/commands/status.py`

职责：

- 人类模式显示 HUD 行
- `--json` 保持全量结构不降级

### Slice D：Team/Ralph 字段补齐（仅必要）

修改：

- `beacon/utils/subagent_runtime.py`（team HUD 增补最小字段）
- `beacon/utils/ralph_runtime.py`（保证 round/stop/circuit 可稳定读取）

注意：

- 不新增命令
- 不改现有 artifact 主路径

## 6. 测试计划（场景测试）

新增测试：

- `tests/utils/test_minimal_hud.py`

最小用例：

1. `S1` 输出 1 行
2. `S2` 输出 2 行（single）
3. `S3` 输出 2 行（team）
4. `S4` 输出 2 行（ralph）
5. `S5` 输出 3 行（warn）
6. `S6` 输出 3 行（blocked/trip）
7. 每行长度不超过 120 字符（极简约束）

回归测试：

- `help/status` 现有 JSON 字段不回归
- `ralph` 与 `team` 现有状态字段可继续被读取

---

## 7. 实施顺序

1. 实现 `minimal_hud` 纯渲染函数 + 单测
2. 在 `help_support` 聚合 HUD payload
3. 在 `help/status` 挂接人类输出
4. 补齐 team/ralph 必要字段
5. 跑场景测试 + 回归测试

---

## 8. 风险控制

| 风险 | 处理 |
|------|------|
| HUD 信息变多影响极简 | 使用字段白名单 + 行数硬限制 |
| 输出改动影响现有解析 | JSON 输出保持兼容，只增不删 |
| blocker 文案不一致 | blocker 统一由 `help_support` 生成 |
| compatibility 迁移路径不明确 | blocker 推荐命令统一指向 `doctor migrate-compat` |

---

## 9. 完成定义

满足以下即完成：

1. `help/status` 能稳定输出 S1-S6 场景 HUD
2. 默认人类面不超过 2 行，告警时最多 3 行
3. 兼容阻断场景有单一推荐命令
4. 单测和回归测试通过
5. 无新增公开一级命令
