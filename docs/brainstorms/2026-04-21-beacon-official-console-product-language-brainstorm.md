# Beacon Official Console Product Language Brainstorm

## What We're Building

Beacon 当前这版可视化已经有页面骨架，但从截图看，仍然明显停留在“原型拼装态”，而不是“官方正式产品态”。问题不只是视觉细节，而是整个产品语言没有收口：

- 中文与英文混杂，没有统一官方命名
- 首页暴露内部技术语义，比如 `Runtime`、`Implement`、`Beacon only`
- 视觉层级不稳定，导航、版本、视图切换、状态标签都在抢注意力
- Hero 区像说明文档，不像正式管理产品首页
- 卡片文案仍然是系统生成感，不像面向负责人/owner 的正式产品表达

所以这次要明确的不是“把页面变好看”，而是：

> Beacon Console 应该采用什么样的官方产品语言，才能看起来正式、规范、可信、可运营。

这层产品语言一旦冻结，后续 requirement/qa/memory/evo/run mode 才能被翻译进统一的官方界面，而不是各自带着内部术语直接上屏。

## Why This Approach

### Approach A: 继续在现有页面上做视觉润色

保留现有首页结构、标签体系和命名，只修按钮、间距、颜色、字号和排版。

**Pros:**
- 成本最低
- 见效最快

**Cons:**
- 只能解决“粗糙”，不能解决“不正式”
- 内部语义仍然会直接露出
- 仍然像 prototype 或 demo，而不是正式产品

**Best when:** 目标只是做一版“更顺眼”的内部看板。

### Approach B: 先冻结官方产品语言，再回写页面

先明确 Beacon 管理端的官方语义体系，包括页面名称、导航命名、状态命名、执行模式命名、风险命名和文案语气，再让 UI 按这个语言体系重做。

**Pros:**
- 能从根上解决“不规范、不正式”
- 最适合把 requirement/qa/memory/evo 闭环翻译成正式产品面
- 后续所有页面、卡片、标签都能统一

**Cons:**
- 比单纯改样式更慢
- 需要克制，不能把所有内部语义都搬到前台

**Best when:** 目标是做可长期维护的官方产品。

### Approach C: 先做完整视觉设计系统

先做品牌、色板、组件库、设计 token、页面模板，再回头定义语义。

**Pros:**
- 设计一致性强
- 长期上限高

**Cons:**
- 顺序错了
- 如果产品语义没定，设计系统会变成空壳

**Best when:** 已经明确了产品语言，只差视觉系统化。

推荐采用 **Approach B**。

原因：

1. 当前问题首先不是“设计不精致”，而是“产品语言不正式”。
2. Beacon 本身承载 requirement、QA、release、memory、evo，这些语义如果不先翻译成官方产品语言，任何 UI 都会继续显得像内部工具。
3. 只要官方语言冻结，视觉系统之后再收会更稳。

## Key Decisions

- 决策 1：Beacon Console 默认必须是“正式管理产品”，不是“AI 工具台”。首页首先回答经营判断与交付判断，而不是展示系统运行感。
- 决策 2：首页不应默认出现内部术语。像 `Runtime`、`Implement`、`Beacon only`、`Portfolio Flow`、`tmux pane` 这类词，不应成为首屏主语义。
- 决策 3：页面语言必须选定单一官方主语言。当前截图中的中英混杂感很强，建议至少在同一页面内统一成正式中文产品语义，英文只作为极少量品牌/版本辅助信息。
- 决策 4：状态词要产品化。不要直接用工程状态名堆标签，而要用稳定的管理语义，例如 `健康 / 关注 / 阻塞 / 待决策`。
- 决策 5：执行模式要降级为二级语义。`single / team / ralph / subagent` 应只在“执行中心 / 恢复诊断”这类二级页面显式出现，首页和项目详情只显示 `执行方式` 或 `交付模式`。
- 决策 6：首页 Hero 不能像说明文档。它应该是一个明确的管理判断入口，而不是一段系统自述。
- 决策 7：可视化产品必须有“官方气质”：克制、清楚、稳定、少术语、少实验感、少炫技。

## Screenshot Findings

从这张图里，可以明确抽出几类问题：

- 命名不统一：
  `Beacon Console`、`Portfolio Flow`、`Beacon only`、`CEO / Owner View`、`Implement`、`Runtime` 同屏混用，像不同层级、不同来源的词拼在一起。
- 视觉主次错位：
  顶部巨大胶囊导航、版本 chip、筛选 chip、Hero 标题、CTA、统计卡都在争第一视觉层级。
- 管理语义不够正式：
  `先回答经营判断，再决定是否下钻` 是对的方向，但文案仍然太像内部设计说明，而不是正式产品表达。
- 工程语义外泄：
  `release-ready`、`revision draft`、`QA blocked`、`Implement` 直接进入首页摘要，像内部 pipeline，不像 owner 面板。
- 标签风格杂乱：
  颜色、圆角、描边、大小、语言都不统一，像“状态贴纸”而不是官方状态系统。
- 品牌与产品气质未建立：
  当前更像“Beacon 生成的一个页面”，而不是 “Beacon 官方管理端”。

## Open Questions

- 官方主语言是否确定为中文产品语义优先，英文只保留品牌和少量版本信息。
- `Beacon Console` 是否继续保留作为顶级品牌名，还是改成更正式的产品名，例如 `Beacon 管理端`。
- 首页是否保留 Hero 区，还是改成更克制的“管理摘要首屏”，减少大面积宣言式横幅。
- `team / ralph` 是否在视觉产品里完全隐藏，只在“恢复诊断 / 执行中心”出现。

## Next Steps

→ 先定义 `官方命名词典`  
→ 再定义 `首页 / 总览 / 项目详情 / 执行中心 / 诊断页` 的正式语义层级  
→ 然后才进入页面重写和视觉实现
