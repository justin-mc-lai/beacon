# Beacon v1.0.3 命令契约（按实现对齐）

> 结论口径：**以 `beacon/commands/*.py` 与 CLI `--help` 为准**。  
> 更新时间：2026-03-06（v1.0.3 完整实现）

---

## 1) 关键纠偏

### 1.1 think vs brainstorm
- `think`：收敛式提问/澄清（`start/status/confirm/question/conflict/summarize`）
- `brainstorm`：7 维发散模板（`create/list`）

### 1.2 workflow vs gate
- `workflow` 主状态机为 **7 阶段**：  
  `think -> user-story -> prd -> test-case -> implementation -> verify -> gate`
- `completed` 判定：必须同时满足  
  `closure_complete == true && gate_pass == true`

### 1.3 resume 契约（flat + action）
- `resume` 是单命令入口，支持 action 语义：
  - `beacon resume <run_id>`
  - `beacon resume restore <run_id>` / `--run-id`
  - `beacon resume continue <run_id>` / `--run-id`

### 1.4 prompt / ask 安全闸（与实现一致）
- `beacon prompt optimize` 默认只出计划，不执行；
- `beacon ask` 默认只出计划，不执行（显式 `--execute` 才执行）；
- `--execute` 阻断条件按顺序评估：
  1) `boundary.state == out_of_scope` → 永远阻断  
  2) `boundary.state == mixed_need_confirm` 且未传 `--allow-mixed` → 阻断  
  3) `confidence < min_confidence` 且未传 `--allow-low-confidence` → 阻断
- `--allow-mixed` 与 `--allow-low-confidence` **通常独立生效**；
- mixed 请求会被边界守卫压低为 `confidence <= 0.59`（默认阈值 0.62）；
- 当 mixed 的低置信度仅由该压降引起时，`--allow-mixed` 可直接放行，不再额外要求 `--allow-low-confidence`。

### 1.5 提示词直达能力边界
- 可直达意图（`SUPPORTED_INTENTS`）：  
  `think / user-story / prd / test-case / workflow / run / status / resume / team / gate / release / doctor / analyze / api-design / data-dictionary / design / jtbd / persona / roadmap / ui-spec / wireframe / version / test-progress / feedback / remember / recall / save / report / init / auto-test`
- doctor 关键词特例：命中 setup/install/uninstall 时可路由到 `doctor setup/uninstall`。
- 非上述意图或越界请求：标记为 `outside-boundary`，回落状态类建议，不直接执行工程实现/部署动作。

### 1.6 推荐触发方式（入口一致性）
- 推荐统一使用：`beacon <subcommand>`（跨环境最稳定）
- `beacon doctor setup` 仅安装 `beacon` 与 `beacon-cli` 启动器，不保证存在 `beacon-<subcommand>` 前缀命令；
- 若必须使用前缀命令，请通过 `pip install beacon-cli`（或 `pip install -e .`）安装完整 console scripts。

## 3) v1.0.3 关键参数契约

### prompt / ask（自然语言路由）
- `prompt optimize <goal>`：默认 `execute=false`
- `ask <goal>`：默认 `execute=false`（显式 `--execute` 执行）
- 两者共享参数：`--allow-mixed`、`--allow-low-confidence`、`--min-confidence`
- 阻断原因统一：`outside-beacon-boundary` / `mixed-boundary-needs-confirmation` / `low-confidence`

### remember / recall（Memory v1）
- `remember add` 支持：
  - `--upsert`
  - `--revision-of <memory_id>`
  - `--reason-code <code>`（repeatable）
- `remember search` 支持：
  - `--mode keyword|semantic|hybrid`
  - `--layer index|timeline|detail`
  - `--ids id1,id2`
- `recall memory` 支持：
  - `--layer index|timeline|detail`
  - `--mode keyword|semantic|hybrid`
  - `--ids id1,id2`

### feedback（自反馈闭环）
- `feedback extract <run_id> [--source gate|auto-test|manual|all]`
- `feedback apply <run_id> [--candidates <path>]`
- `feedback sync <run_id>`（兼容路径：extract + apply）

### workflow（交互 HUD）
- `workflow start/continue` 支持：
  - `--interactive/--no-interactive`
  - `--hud/--no-hud`
  - `--confirm-timeout <sec>`
  - `--on-timeout pause|continue|abort`
- `workflow hud`：只输出 HUD，不推进阶段

## 4) 常见误用 → 正确写法

| 误用 | 正确写法 |
|---|---|
| `beacon-resume restore <run_id>`（仅此一种） | `beacon resume <run_id>` / `beacon resume continue --run-id <run_id>` |
| `beacon-feedback --sync` | `beacon feedback sync [run_id|latest]` |
| `workflow 只有 6 阶段` | workflow 阶段含 `gate`，共 7 阶段 |
| `workflow 无 hud` | `beacon workflow hud --run-id <rid> --json` |
| `--allow-mixed` 可以单独放开 mixed 执行 | mixed 放开后仍会检查 low-confidence，必要时还需 `--allow-low-confidence` |
| `doctor setup` 后一定有 `beacon-think` 等前缀命令 | `doctor setup` 只安装 `beacon`/`beacon-cli`；跨环境建议 `beacon <subcommand>` |
