# 低保真线框页：首页

**平台**: `Web, PC`
**优先级**: `P0`

## 页面意图
- 目标读者：Beacon 管理者 / owner / 负责人
- 页面任务：先回答经营判断，展示项目数、阻塞数、当前交付和介入点。
- 先回答的问题：今天先盯哪些项目，而不是先看所有项目明细。
- 先回答的问题：哪些阻塞已经升级成需要人工介入的经营问题。
- 先回答的问题：当前交付是否继续按版本线推进，还是需要下钻到项目详情。

## 版面拆解
- `经营总览条`: 放在首屏，先建立上下文，让人快速判断当前局面。
- `重点介入区`: 放在主体区，承载该页完成核心判断所需的最小信息块。
- `项目推进摘要`: 放在主体区，先建立上下文，让人快速判断当前局面。
- `当前交付卡片`: 放在主体区，承载该页完成核心判断所需的最小信息块。
- `下一步建议`: 放在收口区，把观察收口成明确动作，避免用户看完后不知道去哪里。

## 信息优先级
- 第一优先看 `经营总览条`，因为页面必须先完成第一轮判断。
- 第二优先看 `重点介入区`，用于补足判断依据并决定是否下钻。
- 最后收口到 `下一步建议`，让用户在读完后知道下一步动作。
- 审阅原则：首屏先给经营判断，不先铺完整表格。
- 审阅原则：阻塞与介入信息必须比常规进度更靠上。

## 关键交互
- `查看管理总览`: 通过 点击项目组合入口 进入 `management-overview`，把当前判断转交到下一层页面完成。
- `进入重点项目`: 通过 点击重点项目卡片 进入 `project-detail`，把当前判断转交到下一层页面完成。

## 状态切换与兜底
- `正常总览`: 展示项目数、阻塞数、当前交付和下一步。
- `阻塞高亮`: 把阻塞项目和介入点提升到首屏。
- `需介入`: 强调需要 CEO / 负责人介入的项目。
- `加载中`: 首页摘要数据仍在汇总。 加载态只保留骨架结构，避免造成页面重新排版。
- `空状态`: 当前没有受管项目。 空态要说明为什么为空，以及下一步该回哪里。
- `错误`: 摘要聚合失败，但提示可以进入详情或 doctor。 页面要优先给出回退或恢复入口，而不是只报错。

## 审阅边界
- 首页不承载 session、agent、原始 requirement 路径等机器噪音。
- 这页只冻结信息结构、交互收口和状态兜底，不表达高保真视觉或最终实现细节。
