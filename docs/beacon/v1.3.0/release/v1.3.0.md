## 当前准确口径

当前应这样理解 `v1.3.0`：

- **已落地**：
  - bounded Codex multi-role team runtime
  - implement-team tmux / HUD
  - qa-team runtime contract
  - 外置角色配置
  - frozen 后的一键开发入口 `implement dev-run`
  - versioned git workflow contract
- **当前稳定运行方式**：
  - Beacon coordinator 先编译 role payload
  - `team worker-run` 负责把 role payload materialize 为 role artifacts
  - `tmux` 负责 session / pane 级并行与观察
  - 正式 writeback 仍由 Beacon stage owner 负责
- **当前正式口径**：
  - `v1.3.0` 是 current runtime release line
  - `docs/beacon/v1.3.0/` 是当前正式文档线

这意味着 `v1.3.0` 当前已经是稳定的 bounded team runtime，但还不是“每个 worker 都是独立 Codex 推理会话”的通用 agent platform。

## 默认配置约束

为保持当前 runtime line 的默认行为一致，全局配置不应再把：

- `skill.preferred`
- `implementation.default_runner`

钉到 `omx` 这类外部 runner。

正确做法是：

- 全局配置只保留可选 runner 定义
- `implement` / `qa` 的默认多代理路径由 Beacon 当前 release line 自己决定
- 外部 runner 通过显式 `--runner` 或项目级配置启用

git workflow 的正确做法还应补充为：

- `beacon.config` 可以提供 branch/worktree/service roots 的 seed
- `implement plan` / `implement sync-git-workflow` / `implement dev-run` 会把这些 seed materialize 到 versioned execution materials
- 一旦 contract 已 materialize，后续 `check-branch` / `doctor verify-git-alignment` / `gate check release` 应优先读取 versioned git workflow contract
