# Beacon v1.3.0 发布线说明

**状态**：已发布 runtime release line  
**日期**：2026-04-10

## 目的

记录 Beacon 下一条版本演进线：受约束的 Codex 原生子代理、统一版本语义、以及“中人 / 英机”的双轨文档治理。

## 当前决定

1. `v1.3.0` 已提升为当前 runtime release line
2. `v1.2.1` 继续作为 partial runtime supplement line
3. `v1.2.0` 转为历史正式版本线

## 已在仓内落地的实现

以下能力已经在仓内落地并验证，并纳入当前 runtime release line：

1. `implement team-plan`
2. `implement team-run --runtime file|tmux|auto`
3. `qa team-plan`
4. `qa team-run --runtime file|tmux|auto`
5. `team worker-run`
6. `team hud`
7. `team page`
8. `implement-team` 的 tmux session / pane 映射
9. `implement-team` 的 HUD JSON / HTML 页面
10. `implement` / `qa` 角色配置外置到：
   - `beacon/team_roles/implement-team.json`
   - `beacon/team_roles/qa-team.json`

其中，`implement-team --runtime tmux` 已完成实机验证：

- 会创建真实 tmux session
- 会为 worker 分配 pane
- 会写出 manifest / role reports / HUD 页面

## 当前准确口径

当前应这样理解 `v1.3.0`：

- **已落地**：
  - bounded Codex multi-role team runtime
  - implement-team tmux / HUD
  - qa-team runtime contract
  - 外置角色配置
- **当前正式口径**：
  - `v1.3.0` 是 current runtime release line
  - `docs/beacon/v1.3.0/` 是当前正式文档线

## 提升前退出标准

1. 阶段级 subagent artifact contract 稳定
2. `implement run` 的 Codex-native adapter 已验证，且保持 `native-single` / `native-team` 兼容
3. `think / user-story / prd / test-case / qa` 的扩面仍保持有边界、证据驱动
4. release/gate 能在不改变 release-truth 模型的前提下理解 delegated runs
5. 下一版本 planning prompt 能稳定进入 `version`，不再误入 QA
6. 版本语义已集中定义，并被主要消费面统一读取
7. 中文人类面与英文机器面双面镜像已通过统一渲染/测试机制锁定
8. `team` 已成为稳定显性 surface，且 implement-team 与 qa-team 保持上下文隔离
9. `implement-team --runtime tmux` 已能稳定产生 session / pane / HUD / role reports
