# 低保真线框页：管理总览

**平台**: `Web, PC`
**优先级**: `P0`

## 页面意图
- 目标读者：管理端值守人 / 组合视角负责人
- 页面任务：提供多项目密集管理视图，稳定扫描版本、阶段、进度、健康态和下一步。
- 先回答的问题：多项目之间谁健康、谁阻塞、谁接近可发布。
- 先回答的问题：是否需要通过筛选和排序快速收敛到一批项目。
- 先回答的问题：什么时候应该从组合视图下钻到单项目接力页。

## 版面拆解
- `筛选与排序条`: 放在首屏，帮助用户先收窄范围，再进入对比与下钻。
- `项目注册表`: 放在主体区，支持快速扫描和定位下一层下钻入口。
- `阶段分布摘要`: 放在主体区，先建立上下文，让人快速判断当前局面。
- `风险与调试摘要`: 放在主体区，先建立上下文，让人快速判断当前局面。
- `推荐 skill 区`: 放在收口区，把观察收口成明确动作，避免用户看完后不知道去哪里。

## 信息优先级
- 第一优先看 `筛选与排序条`，因为页面必须先完成第一轮判断。
- 第二优先看 `项目注册表`，用于补足判断依据并决定是否下钻。
- 最后收口到 `推荐 skill 区`，让用户在读完后知道下一步动作。
- 审阅原则：工具栏必须紧贴项目注册表，减少扫描跳跃。
- 审阅原则：项目注册表承担密集比较，不承担深度解释。

## 关键交互
- `进入项目详情`: 通过 点击项目行或卡片 进入 `project-detail`，把当前判断转交到下一层页面完成。
- `返回首页`: 通过 点击首页导航 回到 `home`，用于撤销下钻并保留上层判断。

## 状态切换与兜底
- `多项目已加载`: 密集展示多项目当前状态。
- `已筛选`: 按阶段、版本、健康态筛选项目。
- `无项目`: 没有任何受管项目进入注册表。 空态要说明为什么为空，以及下一步该回哪里。
- `加载中`: 项目注册表正在聚合。 加载态只保留骨架结构，避免造成页面重新排版。
- `错误`: 总览聚合失败但保留恢复提示。 页面要优先给出回退或恢复入口，而不是只报错。

## 审阅边界
- 总览页只展示管理判断信号，不直接展开 doctor 或 runtime 原始上下文。
- 这页只冻结信息结构、交互收口和状态兜底，不表达高保真视觉或最终实现细节。
