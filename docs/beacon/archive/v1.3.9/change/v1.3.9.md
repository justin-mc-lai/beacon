## 关键变化

### 1. execution 交付面收敛

- QA acceptance 改为同一笔 transaction 双写 machine envelope 与 human-readable execution artifact。
- `release / gate / help / status / doctor / archive` 进一步复用同一 acceptance/readiness truth。
- execution 目录开始从“模板扩张”收敛为“高信号人类面 + machine canonical truth”。

### 2. agents 健壮性与 host runtime 兼容增强

- Beacon 不再把 agents 行为只隐含在 implement 内部，而是显式形成 requirement truth。
- 针对 Codex / Claude Code 的 runtime 差异增加兼容判断、语义阻塞路由与运行时护栏。
- 历史兼容问题已覆盖到 help、release scorecard、review accept 等旧行为路径。

### 3. 第三方 skill admission 与 host-validated compatibility

- 新增 runtime skill admission 能力，Beacon 可以在 host runtime 侧判断某个 skill 是否可被安全接入。
- 保持 Beacon 不替代 Codex / Claude 原生 skill create，而是在 admission / compatibility / validation 层做接入治理。
- 为 `beacon implement --skill ...` 这类高兼容性调用面补齐 requirement、实现与 QA 闭环。

### 4. support-surface friction 治理闭环

- 将旧 `memory-friction-evolution` 主语义升级为统一入口 `beacon-friction-intake`。
- 支持两种入口：
  - `scan`：在 Beacon 源码项目中自动扫描摩擦、阻塞、bug、重复问题
  - `capture`：在目标开发项目中记录人工摩擦上下文
- 两种来源统一进入全局 sqlite 队列治理，支持 `queued / claimed / resolved / reopened / accepted_for_requirement`。
- 默认只进入治理队列，不自动污染 requirement truth；只有显式 accept 后才允许路由到 `prd/change`。
- 保留项目内原始证据 truth，全局 sqlite 只保存治理索引、分类、状态与 refs，支持恢复与 replay。
