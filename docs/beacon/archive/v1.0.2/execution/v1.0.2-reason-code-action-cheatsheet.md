# Beacon v1.0.2 reason_code → 处理动作（值班速查一页）

> 用法：拿到 `reason_code` 后，直接按表执行修复动作，再复验。  
> 范围：覆盖 `beacon/commands/gate.py` 当前定义的 62 个 reason_code。

---

## 0) 先取码（30 秒）

```bash
# 生成 gate 报告
beacon gate check release --mode strict --qa-policy qa9-strict --json > /tmp/gate.json || true

# 查看 reason_code（有 jq 用 jq，没有就直接看 /tmp/gate.json）
jq -r '.issues[] | .reason_code' /tmp/gate.json | sort -u
```

复验统一命令（修完必跑）：
```bash
beacon auto-test create qa9 --project . --require-fresh-evidence --require-junit --require-assertion-count
beacon gate check release --mode strict --qa-policy qa9-strict
```

## 1) 需求/工件类

| reason_code | 处理动作（按顺序） |
|---|---|
| `blocking_open_question_exists` | 在 think 阶段关闭 blocking 问题；必要时补 `beacon think question/confirm/conflict` 后再 summarize。 |
| `boundaries_missing` | 重跑 `beacon workflow start/continue ... --auto` 生成 execution/boundaries.md；或补到 docs/{product,beacon}/{version}/execution。 |
| `boundaries_schema_invalid` | 修复 boundaries.md：非空、标准 markdown（至少含标题与边界条目）。 |
| `terminal_artifact_missing` | 重跑 workflow 终态写入 `terminal.json`；确认 execution 目录有产物。 |
| `terminal_schema_invalid` | 修复 terminal.json 必填：`status`,`traceability`（对象）、`traceability.evidence_refs`。 |
| `terminal_status_invalid` | terminal.status 只允许 `Pass/Blocked/Cancelled`（当前 gate 兼容逻辑）。 |
| `terminal_evidence_missing` | 给 terminal.traceability.evidence_refs 补真实存在路径（相对路径）。 |
| `ac_tc_mapping_gap` | 重跑 `beacon test-case create`，确保 AC 与 TC 一一可追溯。 |
| `coverage_incomplete` | 补缺 story/ac/tc 的执行与证据，直到 coverage 指标完整。 |

## 2) 证据链/一致性类

| reason_code | 处理动作（按顺序） |
|---|---|
| `evidence_ref_path_style_inconsistent` | 统一证据路径为“项目相对 + POSIX 风格”（不以 `/` 开头、无 `\\`）。 |
| `raw_command_log_missing` | 确保有 `.beacon/raw-command-log.jsonl`（重跑 workflow/verify）。 |
| `raw_command_log_invalid` | 修复 JSONL：每行都是 JSON object；空文件视为无效。 |
| `evidence_sha256_manifest_missing` | 确保 `.beacon/evidence-manifest.json` 存在（重跑 workflow 写回证据）。 |
| `evidence_sha256_manifest_invalid` | manifest 必须含 `entries` 或 `items` 且为 list。 |
| `evidence_sha256_manifest_incomplete` | 每个 entry 必须有 `path` + `sha256`。 |
| `evidence_sha256_manifest_mismatch` | 文件缺失或 hash 不一致：删除脏证据后重跑并重建 manifest。 |
| `gate_consistency_report_missing` | 先执行一次 `beacon gate check ...` 生成 `.beacon/gate-report.json`。 |
| `gate_consistency_report_invalid` | 修复 gate-report 字段：`stage/mode/status`；issues 必须是 list。 |
| `gate_consistency_report_mismatch` | gate-report 显示 Pass 但含 blocked issue：修正 status 或修复 issue。 |
| `gate_consistency_conflict` | gate-report 显示 Blocked 但无 blocked issue：修正 status 或补真实 issue。 |
| `report_result_mismatch` | auto-test 汇总 status 与 layer 结果冲突：重算/重跑并保持一致。 |

## 3) scope / memory 治理类

| reason_code | 处理动作（按顺序） |
|---|---|
| `scope_guard_violation` | 清理高风险越界 proposal；必要时拆分需求或回退变更。 |
| `scope_guard_confirmation_pending` | 对高风险 proposal 给出人工确认（A/B/C），再重跑 strict。 |
| `memory_lifecycle_missing` | 重跑 workflow 产生完整 lifecycle（started/context/finished/writeback）。 |
| `memory_evidence_missing` | 给生命周期事件补 evidence_ref（至少关键阶段有证据）。 |
| `memory_feedback_unsynced` | 执行 feedback 同步并落盘；确保反馈与当前 run 对齐。 |
| `release_memory_profile_invalid` | 按 release profile 补齐 required evidence（state/raw-log/auto-test/gate-report）。 |
| `memory_run_selector_drift` | 显式指定 `--run-id/--version/--feature`，避免选错 run。 |

## 4) 测试执行链路类

| reason_code | 处理动作（按顺序） |
|---|---|
| `test_execution_missing` | 先跑 `beacon auto-test create qa9 ...` 生成 `.beacon/auto-test-status.json`。 |
| `test_key_actions_missing` | UI 关键动作缺证据：补 login/register/browse/submit-form 行为与证据。 |
| `ac_tc_evidence_chain_broken` | 每个 TC 必须有 evidence_path 且文件存在；补回填或重跑执行。 |
| `execution_fingerprint_missing` | 通过层必须有 `execution_fingerprint`；修执行器输出后重跑。 |
| `execution_fingerprint_mismatch` | 指纹重复/冲突：清理复用证据，重跑生成唯一指纹。 |
| `evidence_replay_detected` | 证据疑似复用：开启 fresh evidence，确保路径包含当前 run_id。 |
| `evidence_timestamp_out_of_window` | 通过层缺 started_at/ended_at：补时间戳并重跑。 |
| `assertion_count_zero_pass` | 调整测试命令输出可解析断言数（>0）再执行。 |
| `junit_missing_or_invalid` | 让每层通过测试输出合法 junit.xml（包含 testsuite/testsuites）。 |
| `flaky_rate_exceeded` | 先稳态修复 flaky，再重跑；必要时降并发/加重试后修根因。 |

## 5) QA9 矩阵与策略类

| reason_code | 处理动作（按顺序） |
|---|---|
| `qa9_matrix_missing` | 执行 `beacon test-case create "<feature>" --version v1.0.2 ...` 生成 qa9-matrix。 |
| `qa9_matrix_schema_invalid` | 对齐 schema：`qa_types/qa_requirements/entries` 等必填字段。 |
| `qa9_required_type_missing` | 补齐 `--require-qa-types` 指定的类型到 qa9 matrix。 |
| `qa9_waiver_missing_approval` | `applicability=na` 时必须有 waiver 对象（ticket/approved_by/expires_at）。 |
| `manual_waiver_unapproved` | waiver 缺审批人：补 `approved_by`（并建议补审批票据）。 |
| `qa9_ac_traceability_broken` | entries 中每个 TC 都要有 `ac_id`。 |
| `qa9_command_missing_auto_case` | automation=auto/hybrid 的 TC 必须有 command。 |
| `qa9_automation_rate_below_target` | 提高 auto case 命令覆盖，或确认阈值参数是否合理。 |
| `qa_llm_plan_missing` | 补 `llm_plan` 节点。 |
| `qa_llm_plan_invalid` | 修 `llm_plan.mode/model`。 |
| `qa_llm_project_scan_missing` | 补 `llm_plan.project_scan`（language/framework/frontend/risk_points）。 |
| `qa_llm_skip_without_rationale` | llm disabled 时补 `skip_reason`。 |

## 6) 契约/集成/兼容性专项类

| reason_code | 处理动作（按顺序） |
|---|---|
| `contract_spec_missing` | 在 QA9 entries 补 contract 用例，并关联 spec（openapi/pact 等）。 |
| `contract_verification_missing` | 执行并通过 contract 层（status=passed）。 |
| `integration_env_missing` | 补集成环境前置（依赖服务、测试数据、凭证）并重跑。 |
| `integration_execution_missing` | 补 integration 条目并执行通过。 |
| `compatibility_matrix_missing` | qa9 matrix 补 `compatibility_matrix`。 |
| `compatibility_axis_incomplete` | 补齐 browsers/devices/required_pairs。 |
| `compatibility_execution_missing` | 执行 compatibility 层并通过（建议 Playwright 多 project）。 |

## 7) 架构治理预留码（当前版本通常不主动触发）

> 以下码在 `REASON_CODES` 中定义，其中 `evidence_integrity_missing` 已在 release strict 主路径启用。

| reason_code | 处理动作 |
|---|---|
| `arch_artifact_missing` | 补 architecture 决策文档与边界说明，纳入 execution 证据链。 |
| `ownership_boundary_unclear` | 明确模块 owner、职责边界、升级路径。 |
| `api_contract_drift` | 对齐 API 契约文档与实现，补兼容策略。 |
| `nfr_budget_unproven` | 补性能/可靠性/安全预算验证证据。 |
| `evidence_integrity_missing` | 检查 `.beacon/evidence-signature-chain.json` 是否存在且包含当前 run_id；必要时重跑 auto-test。 |

## 8) 升级处理（何时拉人）

满足任一条件立即升级给 Tech Lead/QA Lead：

1. 同一 reason_code 连续 3 次复发  
2. `evidence_replay_detected` / `execution_fingerprint_*` 持续出现  
3. `--force` 被要求用于生产发布  
4. `qa9_required_type_missing` 在 release 前仍未清零
