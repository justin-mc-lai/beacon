# Beacon v1.0.2 术语表（人机协同版）

> 目标：统一语言，减少误解；让 PM/QA/Dev/AI 在同一语义层协作。

---

## 1. 工作流与运行术语

| 术语 | 定义 | 说明 |
|---|---|---|
| Workflow | Beacon 端到端主流程 | think → user-story → prd → test-case → implementation → verify |
| Stage | 工作流阶段 | 每个阶段都有输入/输出与 gate 条件 |
| Run ID | 一次流程执行唯一 ID | 常见格式：`run-YYYYMMDD...` |
| Lifecycle Event | 阶段生命周期事件 | stage_started / stage_finished / stage_failed |
| Terminal Status | 流程终态 | completed / blocked / cancelled |
| Next Step Selector | 结束后下一步引导 | OMC / OMX / Beacon team / continue |

---

## 2. 需求与测试术语

| 术语 | 定义 | 说明 |
|---|---|---|
| AC (Acceptance Criteria) | 验收标准条目 | 需求可测性核心单位 |
| TC (Test Case) | 测试用例 | 必须可执行、可验证、可追溯 |
| AC→TC Traceability | AC 到 TC 的映射关系 | Gate 检查重点 |
| QA9 | 9 类测试分类体系 | unit/interface/contract/integration/smoke/functional/regression/exception/compatibility |
| QA Profile | QA 类型组合模板 | web-core / web-full / custom |
| QA Applicability | 某 QA 类型适用性 | required / conditional / na |
| Waiver | 豁免 | `na` 必须审批（ticket/approved_by/expires_at） |

## 3. 产物与证据术语

| 术语 | 定义 | 说明 |
|---|---|---|
| qa9-matrix | QA9 用例矩阵 JSON | `*.qa9-matrix.json` |
| auto-test-status | 自动化执行汇总 | `.beacon/auto-test-status.json` |
| Evidence | 执行证据 | command/stdout/stderr/junit/result/report |
| Evidence Freshness | 证据新鲜性 | 当前 run_id 产生，不可复用旧证据 |
| Execution Fingerprint | 执行指纹 | 用于识别伪造/复用 |
| JUnit Valid | JUnit 结构有效性 | passed 必要条件之一 |
| Assertion Count | 断言数量 | passed 必须 > 0 |

## 4. Gate 与治理术语

| 术语 | 定义 | 说明 |
|---|---|---|
| Gate | 发布前治理检查器 | 判定是否可放行 |
| Gate Mode | 检查模式 | strict / normal / debug / dry-run |
| QA Policy | QA 检查策略 | legacy / qa9-core / qa9-strict |
| Reason Code | 标准化失败原因码 | 用于阻断与统计治理 |
| Blocked | 阻断状态 | 不可继续发布 |
| Force Pass | 强制放行 | 高风险操作，需记录审批理由 |
| Scope Guard | 范围防失控机制 | 高风险 proposal 需人工确认 A/B/C |

## 5. 人机协同术语

| 术语 | 定义 | 说明 |
|---|---|---|
| Human-in-the-loop | 人在环控制 | 关键决策点必须人工确认 |

## 7. 团队沟通最小词典（建议）

- “**通过**”= gate pass，不是单条测试 pass  
- “**完成**”= workflow terminal completed 且 release gate pass  
- “**可发布**”= strict gate 无 blocked reason_code  
- “**证据完整**”= traceability + fresh evidence + junit/assertion + report consistency  
- “**可豁免**”= 有审批单、审批人、到期时间

---

## 8. 常见误解纠偏

1. **误解**：auto-test passed = 可发布  
   **纠偏**：必须再过 gate strict  

2. **误解**：LLM 建议就是最终方案  
   **纠偏**：LLM 只提供 proposal，人类负责 approval  

3. **误解**：`--force` 是正常流程  
   **纠偏**：`--force` 是应急流程，必须留痕并复盘
