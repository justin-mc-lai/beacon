# Brainstorm：提升 Beacon AI Agent 实用性与用户体验（v1.1.1 迭代）

**日期**：2026-03-12  
**主题**：在“产物文档管理工具”定位下，提升 AI Agent 对 Beacon 的实用性与用户体验  

> 约束前提：
> - Beacon 只负责把「需求想法」转化为「可交付证据」（PRD/用户故事/测试用例）
> - 不做代码实现与工程细节（仅支持外部链接）

---

## 维度一：用户维度

**核心用户是谁？**

| 用户类型 | 典型角色 | 关键诉求 | 典型痛点 |
|---|---|---|---|
| 专业高频 | 产品经理 / 需求负责人 | 快速产出高质量证据 | 产物不一致、评审反复 |
| 专业高频 | QA / 测试负责人 | 结构化用例、可追溯 | 需求变更导致用例失效 |
| 管理/评审 | 项目/研发负责人 | 可交付证据、可追踪 | 缺少“可交付感”与版本差异 |
| 代理用户 | AI Agent（协作对象） | 低摩擦上下文 + 可控输出 | 认知断点、输出不可控 |

**扩展问题**
- 潜在用户：研发、运营、客户支持（需要可交付证据）
- 排斥用户：只想做脑暴记录、或只做代码实现的人

---

## 维度二：场景维度

| 场景类型 | 具体场景 | AI Agent 价值点 |
|---|---|---|
| 工作场景 | 需求评审前 1-2 天 | 快速生成证据链 + 评审摘要 |
| 工作场景 | 迭代变更后 | 自动同步 PRD/US/TC 变更差异 |
| 专注时间 | 周期性梳理版本范围 | 生成版本证据包 + 交付清单 |
| 碎片时间 | 会议后快速整理 | 将会议纪要转为产物草稿 |

**触发场景**
- “我需要提交可交付证据”
- “需求变更了，用例要跟上”
- “评审要求可追溯证据链”

**连续场景**
- 使用前：想法/纪要/截图/工单链接
- 使用后：评审、签收、同步到工程/测试执行

## 维度三：业务维度

**核心价值（内部效率）**
- 降低产物交付成本（节省 PM/QA 时间）
- 提升评审通过率（减少反复沟通）
- 提高交付可追溯性（可审计、可复盘）

**竞品参考**
- 竞品A：Notion（灵活但缺链路）
- 竞品B：Confluence + Jira（强协作但门槛高）

**差异化机会**
- “证据链 + 证据包”内建，无需自建体系

# 收集想法（Idea Pool）

## AI Agent 实用性
1. **结构化上下文采集器**：收集“需求要素清单”（目标/范围/用户/场景/约束）
2. **证据链生成器**：一键生成 PRD + 用户故事 + 测试用例
3. **变更影响分析**：需求改动 → 自动标记受影响的 US/TC
4. **质量闸门**：缺项提示（如：验收标准缺失、边界未定义）
5. **输出可信标记**：AI 生成内容标记可信度 + 需人工确认项

## UX 体验提升
1. **证据包视图**：一屏聚合 PRD/US/TC + 导出按钮
2. **向导式流程**：分步式“想法→证据链”流程引导
3. **版本差异视图**：清晰展示改动前后差异
4. **轻量评审/签收**：支持评审意见→结论→签收记录
5. **可交付状态**：完成度徽章（草稿/待评审/已交付）

## 与外部系统边界
1. **仅链接工单/代码**：保持边界
2. **交付包输出标准格式**：Markdown/PDF/链接

---

# 聚类关联

1. **证据链体验集群**：向导 + 证据链生成 + 证据包
2. **可信度增强集群**：质量闸门 + 可信标记 + 版本差异
3. **交付感集群**：导出包 + 状态徽章 + 轻量签收
4. **边界稳定集群**：外部链接，不做实现

---

# 收敛优先级（建议方向）

**P0（必须）**
- 证据链向导（Idea→PRD→US→TC）
- 一键证据包（导出/分享）

**P1（重要）**
- 变更影响分析 + 差异视图
- 质量闸门（缺项提示）

**P2（优化）**
- 轻量评审/签收
- 可信度标记与完成度徽章

---

# 结论（方向确认）

- **AI Agent 价值应集中在“结构化 + 可信 + 可交付”**
- **用户体验核心在“证据链 + 证据包 + 可追溯”**
- **严格保持职责边界**，仅做产物管理与证据交付
