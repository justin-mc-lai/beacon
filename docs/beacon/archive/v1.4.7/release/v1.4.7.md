## Post-Release Read-Model Addendum

After `v1.4.7` runtime promotion, Beacon release/status read models were patched to preserve correct behavior for repos that still operate on historical docs lines such as `v1.0.0`.

This addendum closes a runtime-governance projection bug where historical docs lines could be misread as if they had already adopted newer release-era contracts from later runtime lines.

The corrective slice includes:

- release-facing gates now distinguish:
  - runtime capability awareness
  - docs-line release-governance adoption
- historical docs lines are no longer falsely blocked by later-era release checks for:
  - semantic contract
  - implement prompt boundary
  - evidence-manifest release enforcement
  - test-contract release governance
- cross-version release scorecard selection no longer reuses another version's QA feature scorecard
- status board output no longer prints non-applicable historical-line release noise such as:
  - `semantic: fail`
  - `technical_review: blocked`
  - `release.exhaustiveness: blocked`

Install-mode verification for the real project `slow_uni_bmtop` confirmed:

- `beacon release check v1.0.0 --project ... --json` returns:
  - `status = pass`
  - `release_ready = true`
- `beacon status --board --feature miniapp-ui-visual-refresh` returns:
  - `board.blocker = none`
  - `board.health = healthy`
  - `release.ready = True`

This is a read-model/runtime-governance correction. It does not change the frozen product truth or QA truth of `slow_uni_bmtop`; it only restores correct Beacon interpretation of that existing truth.
