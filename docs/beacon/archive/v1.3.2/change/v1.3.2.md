# Beacon v1.3.2 Change Summary

## Release scope

`v1.3.2` closes the current iteration around three production features:

1. `beacon-v1.3.2-implement-three-modes-and-iterative-browser-qa`
2. `beacon-v1.3.2-karpathy-boundary-defaults`
3. `beacon-v1.3.2-lighthouse-project-analysis-toolkit`

## Added

- `implement` now exposes a stable three-mode execution model around `single`, `team`, and `ralph`.
- `qa` is promoted into an iterative browser-first execution plane with repair handoff and scorecard closure.
- `help` now surfaces implement mode, runner, Ralph round state, and browser runner visibility.
- `lighthouse` adds a minimal single-entry analysis toolkit with fixed templates and default output paths.
- Karpathy-style boundary defaults are now materialized into global boundary diagnostics, technical review contracts, and QA evidence.

## Changed

- README and root `SKILL.md` are aligned back to the current runtime release line `v1.3.1`.
- `v1.3.2` formal package docs now include project-skill / QA evolution guidance and source architecture indexing.
- the slimming PRD is moved out of `v1.3.2` and deferred to the `v1.3.3` line.

## Verification summary

- implement-three-modes feature QA closed with full 33-case QA9 coverage and acceptance writeback.
- `review quality` passed for the feature after formal package closure docs were restored.
- `review accept` completed for the feature and closed the implementation plan progress state.

## Boundary note

`v1.3.2` keeps Beacon on the minimal public workflow:

```text
prd
→ user-story
→ test-case
→ implement
→ qa
→ release
```

All team/subagent/runtime complexity remains machine-internal by default.
