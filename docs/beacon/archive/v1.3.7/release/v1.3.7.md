# Beacon v1.3.7 Release Note

## Release Type

- delivery release line: `v1.3.7`
- runtime release line: `v1.3.7`
- canonical docs line: `docs/beacon/archive/v1.3.7/`

`v1.3.7` closes two feature lines on top of the existing host-native kernel and promotes them into the repository's current public runtime line. This release packages a stricter implementation delivery truth model plus a built-in brainstorming sidecar as part of the promoted runtime contract.

## What Ships In v1.3.7

1. Canonical implementation delivery baseline envelope
   - implementation delivery baseline becomes the only truth source for implementation projections.
   - deterministic implementation contract, git workflow contract, and implementation plan are one-way projections.
   - gate blocks projection drift against canonical metadata and delivery scope.

2. Frozen-truth-aware implement closure
   - implement flow can verify work directly against frozen `prd / user-story / test-case`.
   - prompts that imply new scope, story expansion, or acceptance movement must route to change/refreeze instead of mutating truth implicitly.

3. Built-in `beacon-brainstorm` sidecar
   - Beacon now includes a host-visible brainstorming sidecar for continued requirement convergence and project evolution analysis.
   - brainstorm is version-grounded, read-only against frozen truth, and outputs standalone markdown rather than lifecycle truth.
   - first principles, Socratic questioning, and Occam's razor are part of the sidecar thinking contract.

## Release Boundary

- In scope:
  - `docs/beacon/archive/v1.3.7/` requirement, execution, QA, release, and change materials
  - canonical delivery baseline generation and projection consistency enforcement
  - built-in brainstorm sidecar and its verification closure
- Out of scope:
  - allowing brainstorm outputs to overwrite frozen requirement truth
  - allowing projection documents to act as parallel truth sources
  - creating a new public lifecycle stage beyond the promoted 7+3 host-visible surface
