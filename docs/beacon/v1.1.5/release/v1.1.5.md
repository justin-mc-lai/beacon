# Release: v1.1.5

## Summary
v1.1.5 定义 Beacon 的下一阶段正式交付结构：
- human primary surface
- machine secondary surface (`.machine`)
- memory 4-layer architecture
- doctor destructive repair scope

## Scope
- requirements-only release stub
- no runtime implementation in this package

## Implementation Readiness

v1.1.5 当前应视为：

- requirements-ready
- implementation-pending
- not release-ready

原因：

1. materials 已形成完整主链；
2. runtime 仍以 `v1.1.4` 为当前实现口径；
3. delivery / gate 尚未形成 v1.1.5 闭环；
4. `auto` 版本解析已经会选到 `v1.1.5`，因此实现前必须先控制版本选择风险。

## Safe Implementation Position

v1.1.5 的实现目标是：

- 重构 Beacon 的 human / machine / runtime 三面边界
- 调整 machine artifact 的正式归位路径
- 收口人类主阅读面
- 强化 doctor 作为修复器的职责

v1.1.5 的实现不应变成：

- runtime orchestration 扩张
- 新 runner 平台化
- 全仓自动研究
- agent lab 式能力膨胀

## Safe Rollout Rule

推荐顺序：

1. 冻结版本选择策略
2. 抽象统一路径层
3. 先改消费端读取
4. 再实现 `doctor` 迁移器
5. 最后切生产者写入路径
6. `eval-lab` 仅实现最小骨架

- `docs/beacon/v1.1.5/execution/safe-implementation-plan.md`
