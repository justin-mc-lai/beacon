# Beacon v1.2.0 Summary

**Theme**: re-center Beacon around the `PRD → user-story → QA` anchor while simplifying commands, strengthening project-skill workflow, and reducing prototype drift  
**Status**: shipped runtime release line  
**Date**: 2026-04-08

---

## One-line summary

`v1.2.0` is the line that makes Beacon's mainline easier to operate, easier to adapt per-project, and harder to drift:

```text
PRD
→ user-story
→ QA
→ implementation evidence
→ review / gate / release
```

---

## Current release focus

The shipped `v1.2.0` runtime line closes three subordinate workstreams under one main goal:

1. command simplification and smart routing
2. project-skill workflow strengthening, including an explicit `beacon skill discover` contract
3. prototype-to-requirement anchoring

These are not peer product centers.
They stay subordinate to one statement:

> make the `PRD/story/QA` chain easier to use, easier to adapt per-project, and harder to drift.

---

## Closed runtime package

This release line is considered closed only when it includes:

1. the mainline anchor contract (`PRD → story → QA → evidence → closure`)
2. a bounded `skill discover` requirement surface for project-skill onboarding
3. story-QA baseline bundle expectations
4. coverage scorecard and bounded `qa auto harness` constraints
5. execution guidance that maps the requirement package onto concrete source touchpoints
6. imported architecture / command / project-skill research convergence from the April 8 deep analyses
7. source-architecture and machine-baseline artifacts that make the package freezeable
8. landed runtime behavior for the bounded `skill discover` / mainline-help / QA baseline requirements
9. release artifacts showing implementation, review, gate, and acceptance closure
