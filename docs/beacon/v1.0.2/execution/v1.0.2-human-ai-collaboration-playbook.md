# Beacon v1.0.2 人机协同操作手册（防失控）

> 目标：让 AI 高效执行、让人类可控决策，避免“自动化跑偏”。

---

## 1. 协同原则

1. **AI 负责生成与执行，人类负责边界与放行**
2. **默认 strict，不默认 force**
3. **没有证据，不算完成**
4. **有阻断码必须闭环，不允许口头通过**

---

## 2. 四个必设控制点（Human Checkpoints）

### CP-1：需求边界确认（Think 后）
- 检查项：open question 是否 blocking
- 人类动作：确认范围、优先级、禁区（out-of-scope）

### CP-2：QA 策略确认（Test-case 前）
- 检查项：qa_applicability、runner_policy、waiver
- 人类动作：确认 required 类型与豁免审批

### CP-3：执行结果确认（Auto-test 后）
- 检查项：pass/failed/blocked、assertion_count、junit、flaky_rate
- 人类动作：判定是否进入 gate

### CP-4：发布确认（Gate 后）
- 检查项：blocked reason_code 是否清零
- 人类动作：仅在 strict pass 时发布；force 必须签字留痕

---

## 3. 推荐操作 SOP

```bash
# 1) 需求与策略
beacon think start "<feature>" --project . --version v1.0.2
beacon user-story create "<feature>" --project . --version v1.0.2
beacon prd create "<feature>" --project . --version v1.0.2

# 2) 用例与执行
beacon test-case create "<feature>" --project . --version v1.0.2 --qa-profile web-full --llm-auto --llm-mode auto
beacon auto-test create qa9 --project . --qa-matrix-path <qa9-matrix> --require-fresh-evidence --require-junit --require-assertion-count

# 3) 治理放行
beacon gate check release --mode strict --qa-policy qa9-strict --min-automation-rate 0.85
```

---

## 4. 角色分工（建议）

| 角色 | 必做动作 | 禁止动作 |
|---|---|---|
| PM/PO | 确认范围与验收标准 | 跳过 AC 审阅直接推进 |
| QA Lead | 审核 QA9 策略与 waiver | 仅看通过率不看证据 |
| Tech Lead | 审核 runner policy 与 gate 规则 | 在 CI 中默认 force |
| AI Agent | 生成产物、执行命令、输出证据 | 自主放行发布 |

---

## 5. 失控预警指标（看板建议）

- `force` 使用次数（周）
- blocked reason_code Top 10
- `qa9_required_type_missing` 发生率
- `assertion_count_zero_pass` 发生率
- `evidence_replay_detected` 发生率
- gate first-pass rate

> 当 force 使用次数连续 2 周上升，需触发流程复盘。

---

## 6. 异常处理策略

1. **阻断码出现**：先修复根因，再重跑同一 stage  
2. **证据不一致**：以 gate 结果为准，禁止人工口头覆盖  
3. **确需 force**：记录 ticket/审批人/影响范围/回滚方案  
4. **模型策略异常**：切换到 rule 模式 + 人工指定 qa_types

---

## 7. 最小治理规则（可直接进团队规范）

- Rule-01：CI 仅允许 `gate --mode strict`
- Rule-02：force 必须审批且 24h 内补复盘
- Rule-03：waiver 无 `approved_by` 一律无效
- Rule-04：release 判定以 gate-report 为唯一事实源
- Rule-05：每次 blocked 必须形成修复记录与二次验证证据
