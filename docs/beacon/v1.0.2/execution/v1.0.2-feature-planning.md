# Beacon v1.0.2 功能规划（QA9 + LLM 自适应闭环）

> 总体架构与流程图请见：`v1.0.2-solution-architecture.md`

## 1. 规划原则

- 先闭环，后扩展：先打通 think → test-case → auto-test → gate
- 真实证据优先：所有 pass 都必须有可验证证据链
- 项目自适应：同一套流程覆盖 AI Agent Skill / Web / API 项目

## 2. 功能分层

### F1 - 项目识别与 QA 策略层（Think）
- 目标：输出可执行 qa_strategy
- 产物：project_type、qa_applicability、runner_policy、command baseline
- 价值：避免“一刀切”测试策略

### F2 - QA9 用例编排层（Test-Case）
- 目标：从 AC 生成可执行 QA9 矩阵
- 产物：`*.qa9-matrix.json`
- 价值：形成标准化 AC→TC 追溯

### F3 - 自动化执行层（Auto-Test）
- 目标：按矩阵执行并生成证据
- runner：browser-use / Cypress / Playwright / agent-browser
- 价值：真实运行数据替代人工口径

### F4 - 回填与统计层（Progress）
- 目标：自动更新 TC 状态与测试汇总
- 指标：cases_total、passed、failed、blocked、pass_rate、automation_rate
- 价值：为 Gate 与发布决策提供统一事实

### F5 - 放行治理层（Gate）
- 目标：strict 模式阻断假证据与假通过
- 手段：reason_code + 证据完整性 + 报告一致性
- 价值：确保 release 决策可信

## 3. 版本路线

### P0（必须）
- think 输出 qa_strategy（含 qa9 applicability）
- test-case 生成 qa9 matrix 并覆盖 required 类型
- auto-test 回填 pass/fail 与 case 统计

### P1（增强）
- Cypress/Playwright runner policy（functional/compatibility 分离）
- test-progress 自动同步，不再手工 update
- workflow verify 自动消费 qa9 matrix

### P2（强验收）
- Gate 深度校验 runner 报告一致性
- compatibility required_pairs 执行完整性校验
- 证据防复用、防回放增强

## 4. 风险与应对

- 风险：LLM 误判 qa_applicability
  - 应对：规则兜底 + 人工 override + waiver 审批
- 风险：跨 runner 报告格式不一致
  - 应对：统一 evidence contract 与解析器
- 风险：假通过绕过
  - 应对：strict gate 默认阻断关键 reason_code

## 5. 命令落地建议

```bash
beacon think start "v1.0.2 QA9 自适应闭环" --project . --version v1.0.2
beacon test-case create "qa9-llm-adaptive-automation-closure" --project . --version v1.0.2 --qa-profile web-full --llm-auto --llm-mode auto
beacon auto-test create qa9 --project . --qa-matrix-path docs/beacon/v1.0.2/qa/test-cases/qa9-llm-adaptive-automation-closure.qa9-matrix.json --ui-runner cypress --require-fresh-evidence --require-junit --require-assertion-count
beacon gate check release --mode strict --qa-policy qa9-strict --min-automation-rate 0.85
```

> 说明：AI Agent 驱动流程建议以 `browser-use` 作为探索与生成层，`playwright/cypress` 作为严格放行回归层。
