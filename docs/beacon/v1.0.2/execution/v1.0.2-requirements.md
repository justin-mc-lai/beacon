# Beacon v1.0.2 需求说明（QA9 自适应闭环）

## 1. 背景

当前 Beacon 已具备 QA9 基础能力，但仍需面向不同项目（尤其 AI Agent Skill）实现：
- 项目识别后自动选择 QA 方式
- 测试生成 → 自动执行 → 结果回填 → Gate 放行的完整闭环
- 针对 Cypress/Playwright 证据的严格校验

## 2. 业务需求（BR）

- BR-001：在同一工作流内完成 QA9 规划、执行、回填与放行
- BR-002：支持项目差异化 QA 策略（ai-agent-skill / web-app / api-service）
- BR-003：输出可追溯测试证据，杜绝假通过

## 3. 功能需求（FR）

- FR-001：think 阶段输出 `qa_strategy`（项目扫描、QA applicability、runner policy）
- FR-002：test-case 阶段按 `qa_strategy` 生成 `*.qa9-matrix.json`
- FR-003：auto-test 支持 qa9 全类型命令注入与真实执行
- FR-004：支持 Cypress/Playwright 混合 runner（functional/compatibility 可分别指定）
- FR-005：执行后自动回填 TC 状态、pass 数、失败数、自动化覆盖率
- FR-006：test-progress 自动同步汇总（不依赖手工 update）
- FR-007：workflow verify 阶段支持 QA9 参数透传并强制校验

## 4. 非功能需求（NFR）

- NFR-001：证据新鲜性（当前 run_id）必须可验证
- NFR-002：passed 必须满足 assertion_count > 0 且 junit 有效
- NFR-003：Gate strict 下关键 reason_code 默认 blocked=true
- NFR-004：CLI 保持兼容（`beacon-<subcommand>` 与 `beacon <subcommand>`）

## 5. Gate 需求（GR）

- GR-001：QA9 必填类型缺失时阻断（`qa9_required_type_missing`）
- GR-002：自动化命令缺失时阻断（`qa9_command_missing_auto_case`）
- GR-003：证据复用/时间窗异常阻断（`evidence_replay_detected` / `evidence_timestamp_out_of_window`）
- GR-004：Cypress/Playwright 报告与汇总不一致时阻断（`report_result_mismatch`）
- GR-005：兼容性矩阵缺轴或未执行阻断（`compatibility_axis_incomplete` / `compatibility_execution_missing`）

## 6. 成功标准

- S-001：QA9 required type 覆盖率 = 100%
- S-002：automation rate >= 0.85（默认）
- S-003：`.beacon/auto-test-status.json.status = passed`
- S-004：AC→TC→Evidence 追溯完整，无 blocked reason_code

## 7. 框架适配结论（本版）

- AI Agent 集成最佳选择：`browser-use`
- 兼容性与严格 gate 主证据：`Playwright`
- 历史 Web 回归资产保留：`Cypress`
- 命令级工具补位：`agent-browser`
