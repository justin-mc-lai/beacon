# Release: v1.1.7

## Summary
v1.1.7 在 v1.1.6 的 lifecycle closure 基础上，正式补入：

- project-specific skill profile
- built-in multi-skill registry
- skill-backed orchestration (`orchestrate run`)
- project-aware verify runner (`verify run`)
- required evidence / must-run acceptance gate
- contract drift diagnosis

## Scope
- runtime release line = `v1.1.7`
- `profile / verify / orchestrate` 已进入 CLI 主命令面
- Beacon 可表达 external project skill（如 `rolo-dev`）
- `review quality` / `review accept` 已接入 project evidence gate
- `help` 已能给出 profile-aware next step

## Delivery Readiness

v1.1.7 当前应视为：

- implemented
- release-ready
- project-aware acceptance-gated

原因：

1. runtime / package / docs 当前线已切换到 `v1.1.7`；
2. project skill / profile / orchestration / evidence gate 已进入代码面；
3. 全量测试已通过；
4. v1.1.7 的 requirement / execution / release 物料已齐备。

## Example Target

v1.1.7 的真实样板目标是：

- 能表达像 Rolo 这样的多服务项目
- 能把 `rolo-dev` 这类外部项目 skill 纳入 Beacon profile
- 能把 `pipeline / gateway smoke / interface verify / log/sql evidence` 纳入 accept gate

这意味着本版 release 的“价值判断”不是只有命令数量，而是：

> Beacon 终于开始具备“项目特定验收路径”的正式建模能力。

## Safe Implementation Position

v1.1.7 的实现目标是：

- 让 Beacon 理解“项目真实验收路径”
- 让 Beacon 不只会生成通用 QA，而是能调项目 skill 执行验证
- 让 accept 依赖 required evidence，而不是只依赖单个测试状态
- 让多服务合同漂移在验收前被识别并阻断

v1.1.7 不应变成：

- 把所有项目运行时硬编码进 Beacon Core
- 把每个项目 skill 重写成 Beacon 内部实现
- 只做 skill 列表展示而不做 required evidence gate

## Rollout Verification

推荐验证：

1. `python3 -m pytest -q`
2. `python3 scripts/sync_skill_commands.py --check`
3. `beacon skill registry list --json`
4. `beacon profile create rolo rolo-uat --example rolo-uat --json`
5. `beacon verify run "<feature>" --profile rolo-uat --json`
6. `beacon gate check release --project-root . --version v1.1.7 --json`
7. `beacon release check v1.1.7 --project .`
