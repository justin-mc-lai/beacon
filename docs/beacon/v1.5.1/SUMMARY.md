# Beacon v1.5.1 Summary

v1.5.1 freezes the truth-map resolver center as the next Beacon truth-source evolution step.

The goal is not to add another JSON truth file. The truth map is a deterministic CLI resolver and static schema contract. Human and machine files generated by the resolver are read models only.

## Frozen Direction

- Establish `truth-map` as the single resolver entry for Beacon truth reads.
- Keep feature-package Markdown as the future canonical truth source.
- Stop treating MD-to-JSON multi-write projection as a product goal.
- Allow JSON only as optional diagnostics, evidence, or rebuild metadata generated from Markdown truth.
- Begin moving CLI and skill consumers away from hardcoded `prd/`, `user-story/`, and `qa/test-cases/` path assumptions.

## Version Boundary

v1.5.1 builds the resolver center and adoption path. It does not complete the hard cutover.

v1.5.2 completes the cutover: `features/<slug>/{truth,tests,tasks,evidence}.md` becomes the normal canonical truth package. Legacy triptych materials become rebuild/absorb artifacts only.
