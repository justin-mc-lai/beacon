# Change: QA Evo Deep Evidence-Bound AC-Aware Closure

**Feature**: `qa-evo-deep-evidence-bound-ac-aware-closure`  
**Version**: `v1.4.10`  
**Status**: `refreeze-input`  
**Date**: `2026-05-24`

## 1. Change Reason

The v1.4.10 QA evo-deep contract introduced governed output topology, routeable finding families, round-memory boundaries, and Skill Eval Kit scaffolding. Follow-up QA showed that the public `beacon qa evo-deep` output can still be a valid empty skeleton: findings are generated by family, but `affected_ac_ids`, `state_or_flow_refs`, and `current_evidence_refs` can remain empty.

That is sufficient for the v1.4.10 P0 contract, but it is not sufficient for the stronger business closure goal: deep QA must prove that it read requirement truth, formal QA evidence, and release-facing scorecards before claiming a routeable finding set is ready.

## 2. Accepted Change

Freeze a follow-up feature that upgrades QA evo-deep from a taxonomy skeleton to evidence-bound, AC-aware deep QA support:

1. `beacon qa evo-deep "<feature>" --project . --version <version>` must read PRD, user-story, test-case, QA scorecard, and AC closure for the target feature.
2. Each finding must bind to at least one `affected_ac_ids` entry and at least one `current_evidence_refs` entry unless it is explicitly marked as a blocked admission.
3. Empty skeleton findings must fail closed and must not be reported as ready.
4. Skill Eval Kit must replay route decision, boundary preservation, and source anchoring, not only validate case schema.
5. QA scorecard and release readiness must surface whether deep findings were formally absorbed by `beacon qa` before they are used as release supplement input.

## 3. Scope

### In Scope

- AC-aware and evidence-bound QA evo-deep findings.
- Required reads from PRD, user-story, test-case, QA scorecard, and AC closure.
- Fail-closed validation for empty `affected_ac_ids` or `current_evidence_refs`.
- Explicit blocked-admission semantics when required source evidence is unavailable.
- Skill Eval Kit replay checks for route decision, boundary preservation, and source anchoring.
- QA scorecard signal for deep finding absorption into formal QA.
- Release supplement signal that distinguishes absorbed deep findings from advisory-only findings.

### Out Of Scope

- Replacing `beacon qa run` with `qa-evo-deep`.
- Turning QA evo-deep into a release verdict.
- Browser automation implementation.
- New project lifecycle hook behavior.
- Ralph long-task checkpoint controller.
- Automatic project skill injection.
- Changing already released v1.4.9 or v1.4.10 requirement truth packages outside this new feature.

## 4. Route Decision

- This finding is accepted as a new v1.4.10 follow-up change package.
- The source finding came from `beacon-qa-evo-deep` analysis of v1.4.10 behavior.
- Downstream implementation may start only after this change/refreeze transaction is complete.
- Existing v1.4.10 release evidence remains valid for the prior P0 contract; this feature freezes the next stronger closure requirement.
