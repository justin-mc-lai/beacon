# Beacon v1.1.9 Release Notes

**Release line**: `v1.1.9`  
**Status**: Implemented and locally verified  
**Date**: 2026-03-28

---

## One-line summary

v1.1.9 lands Beacon’s **control / recovery / learning overlay** on top of the existing delivery kernel, and makes feature-aware QA, story-exhaustive execution, release scorecarding, keep/discard learning, and browser evidence chaining part of the actual product surface.

---

## Landed capabilities

### 1. Feature-aware QA entry and completion split
- `beacon qa run <feature>`
- `beacon qa evolve <feature>`
- `implementation_done` vs `evidence_done`
- feature QA status under `.beacon/qa/features/<feature>/`

### 2. Story-sequential scenario closure
- `story-scenario-map` machine artifact
- browser-relevant AC expansion into:
  - `happy`
  - `negative`
  - `boundary`
  - `recovery`
  - `compatibility`
- `--mode story-exhaustive`
- dependency-aware stop / block behavior

### 3. Browser evidence chain
- exploratory browser runner contract
- deterministic replay contract
- browser evidence pack
- session-aware runner evidence:
  - session manifest
  - cookies ref
  - storage-state ref
  - runner report
  - browser task
  - transcript / URL / DOM / console / network refs

### 4. Exhaustiveness + release scorecard
- exhaustiveness report persisted per feature
- gate/release can consume:
  - missing scenario families
  - missing replay
  - missing browser evidence pack
  - score / threshold
- release scorecard now summarizes:
  - gate
  - QA mode
  - exhaustiveness
  - learning scorecard
  - latest evo experiment

### 5. Learning-plane skeleton
- benchmark corpus refresh
- keep/discard decision engine
- evo harness contract + scorecard contract
- fixed-budget experiment runner

## Known boundary

v1.1.9 lands the closure skeleton, but it does **not** yet finish the next-step precision loop:

- calibrated confidence
- closure outcome taxonomy
- abstain / review-required semantics
- QA audit labels as benchmark truth
- autoresearch-driven QA precision optimization

Those move to `v1.1.10`.
