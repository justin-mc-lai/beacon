# Beacon v1.3.10 变更摘要

**版本**: `v1.3.10`  
**状态**: `curated`  
**更新时间**: `2026-04-30`

## 版本结论

`v1.3.10` 当前已完成版本材料收口、实现闭环和 proof 收口，但还没有声明为正式 `release-ready` 版本。

当前版本结论是：

- requirement truth materials: `curated`
- implementation: `completed for current scope`
- proof: `completed for requirement-package remediation surfaces`
- release status: `not yet promoted`

## 本次范围

`v1.3.10` 本轮收口 1 条主线：

1. `beacon-v1.3.10-project-topology-and-version-branch-metadata-transaction-governance`

## 关键变化

### 1. 项目拓扑与版本分支元信息治理正式入核

- 新增项目级与版本级两层 metadata 模型。
- 核心字段边界固定收敛为：
  - topology
  - service binding
  - participating services
  - per-service allowed working branch
- 明确复杂 `integration/testing/uat` 协作流不进入 Beacon 核心 metadata。

### 2. 人类面元信息 support surface 固定为 `doctor metadata`

- 宿主命令面固定收口到：
  - `beacon doctor metadata show`
  - `beacon doctor metadata create`
  - `beacon doctor metadata update`
  - `beacon doctor metadata delete`
  - `beacon doctor metadata list`
  - `beacon doctor metadata verify`
- 不新增新的一级公开命令。

### 3. requirement package dual-write 变为强门禁

- `freeze` 会同步 machine requirement package。
- `reopen` 会同步 active machine projection。
- `implement / qa / release` 会在 requirement package 漂移时阻断。
- `doctor sync-materials` 降级为 repair / rebuild，而不是 change-loop 主路径。

### 4. support surface 显式暴露 remediation 路径

- `help` 会在 requirement package 问题时显式给出推荐动作。
- `status --board` 会暴露 requirement package gate、失败分类和 next command。
- `real-project-validation` 会把 `help.next_step` 一并带入 proof。

## 新增 / 调整的主要能力

- 新增项目元信息治理命令面与验证逻辑
- 新增 requirement package drift gate
- 新增 requirement package failure categories
- 新增 real-project proof 对 remediation 路由的显式捕获

## 修复重点

- 修复 `freeze / reopen` 后 requirement package 仍需手动 sync 的闭环缺口
- 修复 `help / status` 对 requirement package 漂移只有阻断、没有分流指引的问题
- 修复 `real-project-validation` 无法证明 help 推荐动作的问题

## 验收结论

- `doctor metadata` 主线：已实现并有真实项目验证
- `requirement package dual-write gate`：已实现并有回归证明
- `help / status / real-project-validation remediation proof`：已实现并有回归证明

## 当前 proof 覆盖

已可证明三条 remediation 路径：

1. 文档漂移 -> `beacon-change`
2. 机器面缺件 -> `beacon doctor sync-materials --single-feature`
3. 版本线 requirement gap -> `beacon doctor verify-materials --strict`

## 当前未关闭项

- feature 级 `freeze` 仍受 requirement clarity 阻断，需要补齐 diagram truth / state axes 后再正式重冻
- 但 version-line `verify-materials --strict` 已通过，说明版本材料本身已补齐到可校验状态
