## 6. 关键发现

### 6.1 v1.6.0 truth.md 的占位词问题没有预期严重

AC 行中几乎不存在 TBD/待定/TODO 占位词。这与预期不同。

**可能原因**：
1. v1.6.0 的 truth.md 大多经过多轮 refreeze，占位词在迭代中被清除
2. 真正的问题不在"显式占位词"，而在**隐性空洞**——AC 看似确定但实则是从模板反向推导的，缺乏用户意图支撑

### 6.2 真正的问题在 tasks.md 和 evidence.md

| 问题 | 严重程度 | 说明 |
|------|----------|------|
| orchestrator 55% tasks 未完成但 truth 已 frozen | 🔴 HIGH | truth 冻结了但实现未完成——truth 描述了尚未存在的功能 |
| go-todo-crud-smoke 0% tasks 完成 | 🔴 HIGH | truth frozen 但无任何 task 完成 |
| 8 个 pending deferral 未决策 | 🟡 MEDIUM | 延后项缺乏用户决策，可能是被跳过的需求 |
| TC-042..044 pending | 🟡 MEDIUM | 3 个 AC 的测试未覆盖 |

### 6.3 "冻结空壳"的真实形态

v1.6.0 的问题不是"TBD 占位冻结"而是**"实现未完成的 truth 冻结"**——truth 描述了完整的行为规范（无占位词），但对应的功能实现只完成了一半。这不是 TIG-DC 占位词检查能捕获的问题。

这指向一个更深层的问题：**freeze gate 不检查实现进度**。一个 truth 可以在 tasks 55% 完成时就冻结，这导致 frozen truth 描述了不存在的功能。

## 7. 对 TIG-DC Phase A 的影响

| 原计划 | 诊断后的调整建议 |
|--------|-----------------|
| TIG-DC 占位词检测为 Phase A 核心 | 仍然必要，但**不是 v1.6.0 的主要问题** |
| 用 v1.6.0 truth 作为负例 fixture | v1.6.0 truth 几乎无占位词，不适合做负例 fixture。需要构造含占位的测试 truth |
| Phase A 完成后占位问题解决 | Phase A 解决的是显式占位，但 v1.6.0 的核心问题是隐性空洞（实现进度与 truth 不匹配） |

### 建议新增检查

**TIG-ImplementationProgress**（Phase A 扩展）：

- freeze 前检查 tasks.md 完成度
- 如果 tasks 完成率 < 100%，freeze 应被阻止或至少 warn
- 理由：frozen truth 描述了完整行为，但实现未完成 = truth 与 reality 不一致

这不是占位词问题，而是**truth-reality gap** 问题。TIG-DC 的占位词检查仍然必要（防止新的占位进入），但需要增加 truth-reality gap 检查来捕获 v1.6.0 的实际病理。
