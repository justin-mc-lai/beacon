## 6. 关键发现

### 6.1 v1.6.0 truth.md 的占位词问题没有预期严重

AC 行中几乎不存在 TBD/待定/TODO 占位词。这与预期不同。

**可能原因**：
1. v1.6.0 的 truth.md 大多经过多轮 refreeze，占位词在迭代中被清除
2. 真正的问题不在"显式占位词"，而在**隐性空洞**——AC 看似确定但实则是从模板反向推导的，缺乏用户意图支撑

### 6.2 tasks.md 簿记失同步（已修复）

初步扫描显示 orchestrator 55% tasks 未完成、go-todo-crud-smoke 0% tasks 完成。经验证，这两个 feature 的实现代码全部存在且测试通过——**tasks.md 未勾选是簿记问题，不是实现缺失**。

| Feature | 初步判定 | 修复后判定 |
|---------|----------|-----------|
| go-todo-crud-smoke | 0/12 tasks done | 12/12 tasks done（2026-06-15 勾选，go build + test + race PASS） |
| orchestrator | 35/64 tasks done | 64/64 tasks done（2026-06-15 勾选，beacon-loop 52/53 tests pass） |

### 6.3 真正的问题：隐性空洞 + 簿记失同步

v1.6.0 的 truth 质量问题有两层：

1. **簿记失同步**（已修复）：tasks.md 与实际实现不一致，导致 truth-reality gap 的误判
2. **隐性空洞**（仍存在）：AC 表述确定但缺乏用户意图来源支撑。占位词检测无法捕获这类问题，只有 provenance 追溯和 intent-first 协议能解决

### 6.4 TIG-DC 仍然必要但需要调整

| 原诊断 | 修正后 |
|--------|--------|
| TIG-ImplementationProgress 为核心新增检查 | **簿记失同步不是 gate 问题**——tasks 勾选是人工操作，gate 检查 tasks 完成度会引入新的簿记负担 |
| 占位词是次要问题 | **占位词检查仍是必要防线**——防止新增占位，但不是 v1.6.0 的存量问题 |
| truth-reality gap 是主要问题 | **隐性空洞才是主要问题**——truth 写了确定性表述，但表述来源不可追溯 |
