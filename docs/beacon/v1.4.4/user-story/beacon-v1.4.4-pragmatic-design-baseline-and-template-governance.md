# User Story: Beacon v1.4.4 pragmatic design baseline and template governance

**Feature**: `beacon-v1.4.4-pragmatic-design-baseline-and-template-governance`  
**Version**: `v1.4.4`  
**Revision**: `R1`  
**Status**: `frozen`

## Story

**As a** Beacon maintainer, product/design owner, or implementation operator,  
**I want** Beacon to provide a restrained default design baseline with fixed templates and anti-AI UI/UX rules inside existing surfaces,  
**So that** UI/UX quality improves by default without expanding Beacon into a large design skill family.

## Acceptance Criteria

- AC-001 Beacon freezes a default anti-AI UI/UX baseline contract.
- AC-002 `design-review` evaluates hierarchy, state clarity, interaction coherence, and anti-AI baseline violations together.
- AC-003 Beacon exposes exactly 3 default templates: `restrained-product`, `operator-console`, `editorial-calm`.
- AC-004 the 3 templates explicitly bind to normalized `apple` / `vercel` reference sources.
- AC-005 `prototype` projects selected template truth and anti-AI contract into `DESIGN.md` and preview assets.
- AC-006 `implement` consumes the same template and interaction baseline truth instead of re-inventing the product surface.
- AC-007 `qa` can detect design drift and anti-AI baseline violations as formal acceptance concerns.
- AC-008 external reference repositories remain research inputs and do not become Beacon runtime dependencies.
