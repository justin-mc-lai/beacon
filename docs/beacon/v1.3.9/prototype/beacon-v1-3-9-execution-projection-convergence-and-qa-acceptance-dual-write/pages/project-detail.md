# 低保真线框页：项目详情

**平台**: `Web, PC, App`
**优先级**: `P0`

## 页面意图
- 目标读者：单项目 owner / 接力执行者
- 页面任务：成为接力页，展示版本线、主 PRD、并行 PRD、需求闭环和推荐动作。
- 先回答的问题：这条版本线当前停在哪个阶段，下一步应该推进哪里。
- 先回答的问题：需求闭环是否完整，是否已经具备 implement / qa 的前提。
- 先回答的问题：应该去 runtime、恢复诊断，还是去看项目物料。

## 版面拆解
- `项目头部摘要`: 放在首屏，先建立上下文，让人快速判断当前局面。
- `版本与分支信息`: 放在主体区，承载该页完成核心判断所需的最小信息块。
- `主 PRD 与并行 PRD`: 放在主体区，承载该页完成核心判断所需的最小信息块。
- `需求物料闭环状态`: 放在主体区，承载该页完成核心判断所需的最小信息块。
- `最近交付与下一步`: 放在主体区，把观察收口成明确动作，避免用户看完后不知道去哪里。
- `运行态摘要卡`: 放在收口区，先建立上下文，让人快速判断当前局面。

## 信息优先级
- 第一优先看 `项目头部摘要`，因为页面必须先完成第一轮判断。
- 第二优先看 `版本与分支信息`，用于补足判断依据并决定是否下钻。
- 最后收口到 `运行态摘要卡`，让用户在读完后知道下一步动作。
- 审阅原则：项目头部先建立上下文，再展开需求闭环。
- 审阅原则：主 PRD 与并行 PRD 要并排出现，避免真相散落。

## 关键交互
- `查看运行中心`: 通过 点击运行态摘要 下钻到 `runtime-center`，只在当前页信息不足时继续展开。
- `查看恢复诊断`: 通过 点击恢复诊断入口 下钻到 `recovery-diagnostics`，只在当前页信息不足时继续展开。
- `查看项目物料`: 通过 点击文档查看入口 下钻到 `material-viewer`，只在当前页信息不足时继续展开。
- `返回管理总览`: 通过 点击返回 回到 `management-overview`，用于撤销下钻并保留上层判断。

## 状态切换与兜底
- `可接力`: 版本、PRD、需求闭环和下一步信息完整。
- `需求缺口`: PRD / user-story / test-case 存在缺口。
- `需求草稿`: 需求已建立但未冻结。
- `需求冻结`: 需求链与 prototype 都已冻结。
- `运行中`: 存在 single / team / ralph 运行摘要。
- `加载中`: 项目详情正在聚合。 加载态只保留骨架结构，避免造成页面重新排版。
- `错误`: 详情聚合失败但给出恢复链路。 页面要优先给出回退或恢复入口，而不是只报错。

## 审阅边界
- 项目详情是接力页，不直接承载底层日志和实现细节。
- 这页只冻结信息结构、交互收口和状态兜底，不表达高保真视觉或最终实现细节。
