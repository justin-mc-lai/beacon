# Release: v1.1.4

## Summary

Beacon v1.1.4 ships the implementation adapter surface:

- `beacon skill` for runner/skill adapter management
- `beacon implement` for implementation-stage execution
- workflow integration that delegates implementation to `implement run`
- implementation summary writeback surfaced by `review spec`

## Delivered scope

### CLI

- `beacon skill detect|list|show|register|prefer|doctor`
- `beacon implement list-runners|run|status`

### Runtime / adapter model

- built-in adapters: `omx`, `omc`, `gstack`
- adapter types: `command-skill`, `handoff`
- config sources: project `beacon.config.yaml`, global `~/.config/beacon/config.yaml`
- OMX built-in adapter now targets `omx exec --full-auto --cd ... --skip-git-repo-check ...`

### Evidence / writeback

- `.beacon/implement/<run_id>/request.json`
- `.beacon/implement/<run_id>/result.json`
- `docs/beacon/v1.1.4/execution/implementation-summary-<feature>.{json,md}`
- `review spec` surfaces implementation `artifact_updates`

### Skill standard alignment

- canonical standard skill package: `skills/beacon/`
- compatibility root skill entry: `SKILL.md`
- script wrapper: `skills/beacon/scripts/run_beacon.sh`
- evolution summary: `docs/beacon/v1.1.4/release/version-evolution-changelog.md`
- latest feature usage guide: `docs/beacon/v1.1.4/execution/latest-feature-usage-guide.md`
- real project recipes: `docs/beacon/v1.1.4/execution/real-project-recipes.md`
- FAQ / troubleshooting: `docs/beacon/v1.1.4/execution/faq-and-troubleshooting.md`
- comparison / feature solidification: `docs/beacon/v1.1.4/execution/beacon-vs-openspec-gsd-comparison.md`
