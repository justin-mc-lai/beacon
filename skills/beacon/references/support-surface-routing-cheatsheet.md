# Support Surface Routing Cheatsheet

This is a non-canonical support reference for humans.

Use it when you know the next step should be support-shaped, but you are not sure which support surface fits.

## Quick map

- challenge framing or converge gaps -> `beacon-brainstorm`
- challenge version promise or scope direction -> `beacon-ceo-review`
- challenge product/UI/interaction quality -> `beacon-design-review`
- high-risk structural analysis or test-delta derivation -> `beacon-deep`
- shrink noisy context into a smaller working set -> `beacon-context-engineering`
- keep implementation/review anchored to actual source and evidence -> `beacon-source-driven`
- challenge self-rationalized confidence and expose proof gaps -> `beacon-doubt-review`
- ask what next or recover route clarity -> `beacon-help`
- inspect current status -> `beacon-status`
- repair context or docs drift -> `beacon-doctor`

## Hard boundary

If support output changes accepted scope, promise, or acceptance assumptions, route back to `beacon-change`.
